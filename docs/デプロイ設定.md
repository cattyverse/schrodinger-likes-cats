# デプロイ設定

公開の出し方。ツールチェインそのものは `docs/環境構築.md`。ここでは Cloudflare 側の設定だけ書く。

公開先: [https://cattyverse.com/schrodinger-likes-cats/](https://cattyverse.com/schrodinger-likes-cats/)  
画像: `https://assets.cattyverse.com/schrodinger-likes-cats/{slug}/…`  
リポジトリ: [https://github.com/cattyverse/schrodinger-likes-cats](https://github.com/cattyverse/schrodinger-likes-cats)  
GitHub ユーザー `cattyverse`（Organization ではない）。

---

## 決めたこと


| 項目     | 内容                                                                  |
| ------ | ------------------------------------------------------------------- |
| 置き場    | Cloudflare Workers の静的アセット。Pages ではない                               |
| Worker | コードを持たない。`main` の無い `assets` だけの構成                                  |
| 成果物    | `astro build` の `dist` だけ                                           |
| 起動     | Workers Builds（Cloudflare の Git 連携）。`main` への push                  |
| ビルド    | `npm run build`。デプロイは既定の `npx wrangler deploy`                      |
| ドメイン   | `cattyverse.com`。Route は `cattyverse.com/schrodinger-likes-cats` と同 `/*` の 2 本 |
| 基底     | `astro.config.mjs` の `base: "/schrodinger-likes-cats"`。ローカルも同じ      |
| 404    | `not_found_handling: "404-page"` → `dist/404.html`                   |
| 画像     | R2 バケット `cattyverse`。配信は `assets.cattyverse.com`。ビルドには乗らない             |


GitHub Actions は使わない。Workers Builds が同じことをして、API トークンも GitHub Secrets も要らない。秘密を置かない分だけ手が減る。

Cloudflare Pages も使わない。新機能が来ないため。Workers の静的アセットは同じことができて、あとから Worker のコードを足せる。

`cattyverse.com/` そのものは Route に含めない。CATC の玄関として空けておく。

`docs/` はサイトに出さない。`.gitignore` にある。

## リポジトリ側

### `wrangler.jsonc`

```jsonc
{
  "name": "schrodinger-likes-cats",
  "compatibility_date": "2026-08-18",
  "assets": {
    "directory": "./dist",
    "not_found_handling": "404-page"
  },
  "routes": [
    {
      "pattern": "cattyverse.com/schrodinger-likes-cats",
      "zone_name": "cattyverse.com"
    },
    {
      "pattern": "cattyverse.com/schrodinger-likes-cats/*",
      "zone_name": "cattyverse.com"
    }
  ]
}
```

Route は 2 本要る。`*` は直前のリテラル `/` を要求するので、`…/schrodinger-likes-cats/*` は末尾スラッシュ無しの `…/schrodinger-likes-cats` にマッチしない。1 本だけだと、そのアドレスが Worker に届かず apex のダミーレコードへ抜けてエラーになる。公開 URL を末尾スラッシュ無しで書いている場所があるので、外すと踏む。

`assets.directory` は `./dist`。`./dist/schrodinger-likes-cats` ではない。Workers の静的アセットは、リクエストのパスをこのディレクトリにそのまま当てる。前綴りを剥がさない。だから `astro.config.mjs` 側で `outDir` を `./dist/schrodinger-likes-cats` にして、フォルダの階層を Route のパスに合わせてある。ここを二重に潜らせると `schrodinger-likes-cats/schrodinger-likes-cats/` を探して全部 404 になる。

`main` は書かない。Worker のコードが無いので、すべてのリクエストが静的アセットとして返る。この経路は無料枠（100,000 リクエスト/日）を消費しない。

`run_worker_first` は使わない。使うと、その経路だけ Worker が起動して枠を食い、枯渇したとき静的配信に落ちずに 429 を返す。画像を同じオリジンから出さないのはこれが理由。

Route はここに書いてある。ダッシュボードで作らない。`wrangler deploy` が読んで当てる。

### `.nvmrc`

Workers Builds が Node の版をここから拾う。`package.json` の `engines.node` は下限なので、実際に使う版はこちらで決まる。

### 置かないもの

`.github/workflows/` は無い。`wrangler` も依存に入れない。デプロイコマンドの `npx wrangler` が、そのときの最新を取る。

## Cloudflare 側の設定

ダッシュボードで一度だけやる。

### 1. ゾーンを足す

`cattyverse.com` を Cloudflare に追加し、取得元のレジストラでネームサーバーを Cloudflare のものに変える。Active になるまで待つ。SSL 証明書は自動・無料。

### 2. apex にプロキシ有効のレコードを置く

Route（ホスト名まるごとではなくパスに当てる形）は、ゾーンにプロキシされたレコードがないと当たらない。apex に A `192.0.2.1` をプロキシ ON で置く。`192.0.2.1` は文書用の予約アドレスで実体は無い。プロキシ ON なので、リクエストは Cloudflare のエッジで止まり Route が拾う。OFF だと本当にそこへ行って死ぬ。

Custom Domain は使わない。あれはホスト名を丸ごと Worker に割り当てるので、`cattyverse.com/` が空かなくなる。

### 3. Worker を作って、リポジトリを繋ぐ

Workers & Pages で Worker を作り、Settings → Builds でリポジトリを接続する。Cloudflare Workers and Pages の GitHub App が入る。対象は `schrodinger-likes-cats` だけに絞る。


| 設定        | 値                    |
| --------- | -------------------- |
| ブランチ      | `main`               |
| ルートディレクトリ | 既定（リポジトリの直下）         |
| ビルドコマンド   | `npm run build`      |
| デプロイコマンド  | `npx wrangler deploy`（既定） |


`npm run build` は先に `check` する（`astro check` → `svelte-check` → Biome）。通らなければ `dist` も出ず、デプロイもされない。依存の導入は Workers Builds がやる。dev 依存も要るので、`--omit=dev` にはしない。

無料枠はビルド 3,000 分/月、同時実行 1、タイムアウト 20 分。このサイトは 1 回 1 分に満たないので当たらない。

ビルドコマンドと監視ブランチは、この表がリポジトリ側の控え。実体はダッシュボードにある。

### 4. R2 バケットを作る

名前は `cattyverse`。`cattyverse` 全体で共有し、キーの頭にサイト名を付けて分ける。

```
cattyverse/schrodinger-likes-cats/{slug}/{ファイル名}
cattyverse/schrodinger-likes-cats/{slug}/frames/frame1.svg
```

R2 の有効化には、無料枠の範囲でも支払い方法の登録を求められる。枠内なら請求は出ない。

### 5. R2 にカスタムドメインを付ける

`assets.cattyverse.com`。同じゾーンなので、レコードは Cloudflare が作る。Worker の Route はこのホスト名を含まないので取り合いにならない。

ワイルドカードの Route（`cattyverse.com/*`）は作らない。`img.` まで拾って、R2 のカスタムドメインが Worker に食われる。

### 6. キャッシュを 1 日にする

`assets.cattyverse.com/*` に Cache Rule を当てて Edge TTL を 1 日にする。または rclone のアップロード時にオブジェクトへ `Cache-Control` を持たせる。どちらでもよいが、片方に決めてここに残す。

パージはしない。差し替えたら最大 1 日待つ。

### 7. R2 の書き込みトークン（手元用）

rclone 用。そのバケットの Object Read & Write だけに絞る。GitHub には置かない。手元の rclone 設定にだけ持つ。

## 画像を押す

展示の絵はビルドに乗らない。手元から片方向に押す。

```sh
rclone copy ./src/public/images/schrodingers-cat r2:cattyverse/schrodinger-likes-cats/schrodingers-cat
```

`sync` ではなく `copy`。`sync` は宛先の余りを消すが、R2 にはバージョニングが無いので戻せない。消すときは手でやる。

rclone の remote は S3 互換で作る（provider は Cloudflare、endpoint は `https://<account_id>.r2.cloudflarestorage.com`）。

---

## GitHub Pages をやめる

移行の前に消した。

```sh
gh api --method DELETE /repos/cattyverse/schrodinger-likes-cats/pages
```

`https://cattyverse.github.io/schrodinger-likes-cats/` は 404 になる。転送はしない。Search Console にはまだ登録していないので、URL の付け替えも要らない。

## 入れない

- GitHub Actions（Workers Builds があれば要らない。トークンも Secrets も持たない）
- Cloudflare Pages（新機能が来ない）
- `@astrojs/cloudflare`（SSR しない。`dist` を置くだけ）
- `wrangler` の依存（`npx` が取る）
- `run_worker_first` と R2 バインディング（無料枠を食う。上記）
- 画像を CI から押す仕組み（ビルド環境に実体が無い）

## 確認

ビルドの結果は Cloudflare の Worker → Builds と、GitHub 側のコミットのステータスに出る。落ちたらログを見る。

見るところ: Route 2 本が当たっているか（末尾スラッシュ無しだけ落ちるなら、無印のほうが抜けている）。apex のレコードがプロキシ ON か。Workers Builds が `main` を見ているか。

画像が出ないときは、まず `assets.cattyverse.com` を直接ブラウザで叩く。R2 に無いのか、`imageUrl` の基底が違うのかを分ける。

初回は npm の版に注意する。このリポジトリは `packageManager` に npm 12 を書いていて、`allowScripts` で esbuild の install script を許可している。Workers Builds が別の npm を使うと、ここで転ぶことがある。
