# Schrödinger Likes Cats

"猫好きなシュレディンガー"企画書

何を作るかはここに書く。技術的な持ち方は `docs/概要説明.md`。幅・密度・カードの中の書き方は `docs/レスポンシブ.md`。

---

## コンセプト

遊び場となるようなサイト。いちばんのコンセプトは、**無限の真っ白な空間に展示を置いている**こと。Web はその空間を覗く窓にすぎない。いま主に覗くのはスマホなので、見える形は縦の無限スクロールになる。空間が縦なのではなく、窓が縦なだけ。レイアウトの基準もスマホ。PC で大きくなっても違和感がない程度に止める。PC 向けに使いやすくすることは、今はやらない。

空間を見る順は人それぞれなので、トップの順はランダムで合わせている。新着の列を作っているのではない。

記事を並べるブログではない。名前どおり、猫好きなシュレディンガーが顔である。サイトの印象は、メイン展示のシュレ猫でつける。本体はそこではなく、順次追加していく展示物（論理クイズ、モンティホールの視覚化、など）。

## 訪問者の流れ

1. トップのカード一覧で見つける（偶然）
2. カードの予告で興味を持つ
3. タイトルで開いて、その場で遊ぶ
4. 詳細へで説明を読み、関連から次の展示へ行く（編集した道）
5. タグを押して、同じ系統を新しい順に見る（体系）
6. 索引から、狙った系統へ飛ぶ
7. 実験場で、まだ展示になっていない案を読む
8. この場所が何かを、about で読む

入り口は経路で違う。

- 検索: 詳細。`/{slug}` が本体
- SNS: メイン（トップ）が多い。詳細や、タグ（`/?tag=` や索引）へ直に来ることもある
- 無いアドレス: 404 専用画面。シュレ猫の遊びだけ

サイト内検索は持たない。トップに「最新」「人気」も出さない。見る順は各自に任せるため。体系的に見る基本はタグである。個別のタグ見方にきれいなページ URL は作らない。`?tag=quantum` のように、一覧へ印を付ける。

実体のあるページは次のとおり。


| 場所      | 役割                                  |
| ------- | ----------------------------------- |
| 展示（トップ） | カード一覧。予告の動き。タイトルで遊びをその場に出せる         |
| 詳細      | 遊びと説明と関連。検索の着地                      |
| 関連      | 次の展示へのリンク。片方向でよい                    |
| タグ      | そのタグ（と配下）の展示一覧。登録日の新しい順。入口は `?tag=` |
| 索引      | タグの木。狙って飛ぶ入口                        |
| 実験場     | 案をつらつら書く場所。展示のカード一覧には出さない           |
| について    | about us。CATC を載せる                  |
| 404     | 専用画面。無いアドレスの着地。シュレ猫の遊びだけ。詳細ではない     |

## トップ

アクセスすると、無限の展示空間を縦に覗く。下へ行くと、まだ見ていない展示のカードを読み込む。一度出したカードは消さない。開いた遊びも、高さが展示ごとに違っても残る。追加できる回数には上限がある（技術側）。

- 1 つ目は固定でシュレ猫（顔なので、窓のすぐそこに置く）
- 2 つ目以降は、その人の覗き順として乱数で決まる。アクセスのたび。URL には残さない。リロードで変わる
- 閉じたカードでは箱を持ち上げない。タイトルで開くと、詳細と同じ遊びがその場に出る
- 同時に開くカードを開ける。状態は保存
- 並びは常に 1 列。カードには最大幅がある（FHD の n%。固定値。n はあとで）。窓がそれより狭いときは全幅（スマホ、多くのタブレット）。広いときは最大で止まり、中央。左右は白いキャンバス。横持ち専用の形にはしない
- 出す枚数は、窓を埋める計算。最低 12、足りなければ 12 の倍数。追加も同じ式。縦横を切り替えても、その 12 枚のまとまりあたりに戻る
- いちばん下に着いてから、さらにスクロールすると足す。ローディング（よくある回るやつ）のあいだに HTML を全部取り、揃ってから一気に出す。画像は待たない。20 回目を足した時点でフッター

## カード

記事のサムネイルではない。空間に置いた展示物そのもの。**カード全体を囲う外枠は持たせない。** パネルの線で箱型にしない。白い空間に、タイトル・中身・説明・タグ・詳細へが乗る。一歩スクロールしたあとのキャンバスを、カードで分割しない。

中身は、一番狭い幅（360 CSS px）で組む。広くなっても並びは変えない。窓の幅で形を切り替えない。画面の絵は線画のイラスト。SNS のプレビューだけ、別の横長画像（PNG）。

タイトルや説明、タグ、詳細へには、見やすさのために必要な装飾（文字の地、余白、コントラストなど）を付けてよい。囲いの装飾と、読めるための装飾は別。

並びは次のとおり。

- タイトル。右に、開閉できると分かる印
- 中身。閉じているときは予告の動き。4コマ風（2〜4枚を順に移す）を共通の型にする。次のコマは下からせりあがって、今のコマを押し上げる。最後の次は白にして間を置き、1枚目をパッと出す。画面に入っているあいだだけ進む。外れたら終わり。戻ったら最初から。開くと、詳細の遊びと同じもの
- 一文の説明
- タグ
- 詳細へ

タイトルをクリックすると、中身が切り替わる。遊ぶ／戻るのトグル。詳細ページへは行かない。右の印も同じ操作。押した瞬間の反応（印が向きを変える、少し沈むなど）で、切り替わったと分かるようにする。印の形は応相談。トグルだと分かればよい。

その場で遊びを試せるようにする。ページを跨がないと触れない、だと離脱しやすい。閉じたままでは、箱を持ち上げるなどの本番の操作は出さない。

詳細へは、中身の下に置く別のボタン。`/{slug}` へ行く。タイトルはリンクにしない。カード全面を一つのリンクにもしない。開いたあとの中身は、遊びの操作（ドラッグなど）を受け取る。

タグはその手前で、`/?tag=` へ行く。押しやすいよう余白を広めにする。

主に見るのはスマホなので、カーソル変化だけを手がかりにしない。合図は、閉じているときの予告の動き、タイトル右の印、押した瞬間の反応、下の詳細へ。どの展示もこの型。

タグはカード上では「これは何系か」の印。押すと `/?tag=` の棚へ行く。クエリが無いときだけ、トップのランダム。

タグは木で持つ。段数は固定しない。運用は浅く始める。表示は `科学 > 量子力学` のように道筋で出す。分類の親は分類表から辿り、展示に親を手で書かない。

根タグをヘッダーやフッターにずらっと並べない。

### シュレ猫カード

- タイトル: 猫好きなシュレディンガー
- 閉じた中身: 4コマ風。シュレディンガーと箱 → 持ち上げる → どうなる！？ 次へは下から押し上げ。最後の次は白待ちのあと1枚目。キャプションは付けない。画面に入っているあいだだけ進む。外れたら終わり。戻ったら最初から
- 開いた中身: 詳細と同じ。箱を持ち上げる遊び
- 説明: 猫好きなシュレディンガーがとある思考実験をしているようです。
- タグ: `#思考実験` `#科学` `#量子力学`

## ヘッダー

固定しない。スクロールしたら消える。全ページ共通。ハンバーガーにはしない。空間の窓枠であって、空間そのものではない。**一歩スクロールすれば、もうキャンバス**（展示の空間）だけが見える。

2 段にする。

```
[ シュレ猫ロゴ          タグ検索 ]  ← 1段目。アイコン行。ちょい太い
[ 実験場  について  … ]          ← 2段目。細い。リンクは横スクロール。あとから足せる
```

1段目はサイトの顔。アイコン。シュレ猫がロゴで、押すとトップへ戻る。右がタグ検索。索引への入口はここに置く。2段目に索引を重ねて並べない。

2段目は行き先の列。実験場、について、あと増える部屋もここに足す。幅に収まらなくても折り返さず、横に流す。

タグ検索の中身（索引ページを開くだけか、タグ名をその場で絞るか）は後で詰める。場所は1段目のこのボタン。

## フッター

詳細のいちばん下は関連なので、フッターは置かない。

詳細以外は、同じフッターを置く。トップ、タグ一覧、索引、実験場、について。ヘッダーもフッターも固定しない。貼り付いたナビにしないから、一歩動くとキャンバスになる。読み切ったところ（この一覧の展示が尽きたとき、または追加 20 回目を足したとき。21 回目は無い）に顔がもう一度出る。

中心はシュレ猫のロゴ。押すとトップへ戻る。リンクをずらっと並べる場所にはしない。

---

## タグ一覧（索引）

目的のタグを探すページ。フォルダの階層に見える。遷移はせず、下に開く。個別のタグページは作らない。

入口はヘッダー1段目のタグ検索。

最初は親だけが見える。開くと、上から次の順。

1. そのタグの説明
2. 「一覧へ」（そのタグの展示一覧 `/?tag=`）
3. 子。ボタンっぽく並ぶ。押すとまた同じ型で開く

開くことと、一覧へ行くことは分ける。子を開いただけでは展示の棚に飛ばない。閉じている親も、開いたあとの子も、同じボタンの列に見える。

説明文は分類表の JSON に持たせる。展示の `meta.json` には書かない。長くない一言でよい。空なら説明の枠自体を出さない。

閉じた行の見た目（絵を乗せるか）や、名前で棚を減らす入力は、まだ開けてある。

## タグの棚（`/?tag=`）

索引で「一覧へ」を押した先。またはカードのタグを押した先。整理された展示の列。足し方・残し方・幅の収まりはトップと同じ。順だけ、投稿日の降順。

上から:

1. パンくず（`科学 > 量子力学`）。各段がリンク。押すとそのタグの棚へ
2. そのタグの説明。索引のフォルダを開いたときと同じ文（`tag.json` の `description`）
3. カード（そのタグと配下。投稿日の新しい順）

子フォルダのボタン列は、ここには置かない。子へ降りるのは索引側。棚の上はパンくずと説明だけ。

## 404

無いアドレスの着地。専用画面。詳細へは行かない。ナビにも出さない。

中身はシュレ猫の遊びだけ。トップのカードを開いたとき・詳細の遊びと同一。説明も関連も出さない。窓枠（ヘッダー・フッター）は付ける。トップへ戻れる。

## 詳細

詳細は遊び、説明、関連の 3 つ。遊びは、トップのカードを開いたときに出るものと同一。説明と関連は詳細だけ。検索の着地はここ。

```
タイトル
  ↓
概要
  ↓
遊び
  ↓
説明
  ↓
関連
```

### シュレ猫の遊び

1. シュレディンガーっぽいマスコットと箱がある
2. 箱をドラッグで持ち上げられる
3. 持ち上げているあいだ、シュレディンガーはドキドキする
4. 中に猫がいる。両手を上げて腰をふりふりダンスする。ダンスは 1 枚の画像の左右反転
5. 持ち上げ切ると、シュレディンガーはホッとする
6. ドラッグを離すと、箱は下りる

### シュレ猫の説明

シュレディンガーの猫の思考実験についての説明を簡単に書く。深入りしすぎず、適度な理解感を促す。

---

## 関連

詳細の末尾に載せる。タグの自動一致ではなく、自分で `related.json` に書いた先だけ出す。片方向でよい。双方向にしたければ、両方のファイルに書く。

- 表示: 横スクロール
- 1 件: タイトルつき画像（OGP と同じ PNG）

見た目の細部（サイズ、件数、余白）は応相談。横スクロールと「タイトル＋画像」は崩さない。

## 公開の範囲

最初に揃えるもの:

- トップのカード一覧（1 つ目固定、以降ランダム）
- シュレ猫カード（タイトルでトグル、下に詳細へ）
- シュレ猫詳細（遊び＋説明。遊びはカードを開いたときと同じ）
- 404 専用画面（シュレ猫の遊びだけ。説明・関連は出さない）
- タグを押すと `?tag=` で、そのタグの展示が登録日の降順で並ぶ
- ヘッダー2段（アイコン行 + ナビの横スクロール）。固定しない
- フッター（ロゴ）。詳細以外は同じ。詳細には置かない
- 索引ページ（タグの木）
- 関連の枠（中身は展示が増えてから）
- 実験場の殻と lab カードの型（タイトル・一文・中身スロット）

後で足すもの:

- 2 個目以降の展示
- 実験場の個別の案（monty-hall の文面など）
- についての文面（CATC。CATC の日は開始の周年）
- 関連の見た目の詰め
