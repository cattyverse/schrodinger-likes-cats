# 環境構築

このリポジトリを動かすためのツールチェイン。画面の仕様は `docs/企画書.md`、ファイル配置は `docs/概要説明.md`。ここでは入れたものと、入れないものだけ書く。

`docs/` はサイトに出さない。`src/pages` にも `src/public/` にも置かない。デプロイに上げるのは `astro build` の `dist` だけ。

Astro の `publicDir` は `src/public`。`src/public/images/` と `src/public/styles/` が `outDir` 直下にコピーされる（`public/` という階層は挟まらない）。CSS は `/schrodinger-likes-cats/styles/…`。

`outDir` は `./dist/schrodinger-likes-cats`。`dist` 直下ではない。Workers の静的アセットはリクエストのパスをディレクトリにそのまま当てるので、フォルダの階層を URL の階層に合わせておく必要がある。`wrangler.jsonc` の `assets.directory` は `./dist` のまま。

画像は置き場が二つに分かれる。使い回す部品（slug が `site`。ロゴ、`missing.svg`）はリポジトリにあり、`/schrodinger-likes-cats/images/site/…` で出る。展示の絵はリポジトリに無く、原本は R2、配信は `https://assets.cattyverse.com/schrodinger-likes-cats/{slug}/…`（slug は contents/lab のフォルダ名。kebab。4コマは `{slug}/frames/frame1.svg` から連番、番号は1桁。OGP は PNG）。手元には `src/public/images/{slug}/` に実体を置く（`.gitignore`）。開発中はそちらが出る。切り替えは `scripts/url.ts` の `imageUrl` の中だけ。

公開先: `https://cattyverse.com/schrodinger-likes-cats`（Cloudflare Workers の静的アセット。Route は `cattyverse.com/schrodinger-likes-cats` と同 `/*` の 2 本）。

## ランタイム


| もの      | 版                   | 理由                           |
| ------- | ------------------- | ---------------------------- |
| Node.js | 24.19.0（Active LTS） | npm 12 の下限が Node `^22.22.2   |
| npm     | 12.0.2              | その時点の最新。`packageManager` に記録 |


Node の下限は `package.json` の `engines.node`: `>=24.15.0`。入れた実体は `.nvmrc` の `24.19.0`。

npm 12 は依存の install script を黙って実行しない。Astro が使う `esbuild` は `package.json` の `allowScripts` で許可してある。クローンしたあとは `npm install` だけでバイナリが入る。

## npm パッケージ


| パッケージ             | 区分  | 版の目安             | 役割                                                    |
| ----------------- | --- | ---------------- | ----------------------------------------------------- |
| `astro`           | dep | 7                | 静的生成                                                  |
| `@astrojs/mdx`    | dep | 7                | 詳細の文                                                  |
| `@astrojs/svelte` | dep | 9                | contents の Svelte 5                                   |
| `svelte`          | dep | 5                | peer。動きの本体                                            |
| `typescript`      | dev | **6.0.3**（6 の最新） | 型。`^6` なので 7 には上がらない                                  |
| `@astrojs/check`  | dev | 0.9              | `astro check`。`.astro` と `.ts`。TypeScript 6 の API を使う |
| `svelte-check`    | dev | 4                | `.svelte` の型。`astro check` は Svelte を見ない              |
| `@biomejs/biome`  | dev | 2                | 整形と lint                                              |


Astro の設定:

```js
site: "https://cattyverse.com",
base: "/schrodinger-likes-cats",
```

ローカルの URL も基底付き。`import.meta.env.BASE_URL` をリンクに使う。`http://localhost:4321/` は 404。開くのは `http://localhost:4321/schrodinger-likes-cats/`。

`base` は GitHub Pages のプロジェクトサイトの名残ではない。`cattyverse.com/` は CATC の玄関として空けておき、キャンバスはその下に並べる。

Svelte は `svelte.config.js` で `vitePreprocess()`。contents の動きは Svelte 5。カードはカタログから `cardTemplate.svelte` を `mount` する。差し込む HTML は遊びの partial だけ。外すときは Svelte の `unmount` を呼ぶ。詳細と 404 の遊びは `play.astro` をページに埋め、同じ `play.ts` を `mount` する。

### TypeScript は 6

7 は GA で `tsc` は速い。ただし 7.0 には安定した programmatic API が無く、Astro / Svelte / MDX の型ツールがまだ 6 の API を呼ぶ。`astro check` は 7 だけだと落ちる。7.1 と各ツールが追いついてから上げる。サイトの作り直しにはならない。

`tsconfig.json` は `astro/tsconfigs/strict` を継承する（ここに `strict: true` がある）。本体は `node_modules/astro/tsconfigs/`。自分のファイルが子、Astro のテンプレが親。マージされた結果が「効いている設定」。

自分のファイルに足しているのは次だけ。

- `lib`: `ESNext` と `DOM`（`document` や `HTMLElement`）
- `noUncheckedIndexedAccess`
- `noFallthroughCasesInSwitch`
- `noImplicitOverride`
- `noImplicitReturns`
- `allowUnreachableCode`: false

`exactOptionalPropertyTypes` と `noUnusedLocals` はまだ足さない。前者は JSON の省略欄が厳しい。後者は Biome に任せる。

`astro build` / `astro dev` は、この `tsconfig.json`（継承込み）を **全部は見ない**。Vite が見るのは主に `paths` や `jsx`、型 import の剥がし方。`strict` や `lib`、`noUncheckedIndexedAccess` は型検査用で、`npm run check` とエディタが使う。JS の出力は esbuild が型を捨てて作る。

### 入れない

- Prettier / ESLint とそれらのプラグイン（Biome に任せる）
- React / Vue / Solid
- Tailwind（CSS 直書き）
- サーバーアダプタ、CMS、DB。Cloudflare へ出すが SSR はしない。`@astrojs/cloudflare` は入れない（`dist` を静的アセットとして置くだけ）
- 状態管理ライブラリ、ゲームエンジン
- TypeScript 7（上記のとおり）
- `wrangler`。デプロイは Workers Builds の `npx wrangler deploy`。そのときの最新を取る。版は固定しない
- GitHub Actions の workflow。`.github/workflows/` は持たない
- R2 の SDK。ビルドも実行時も R2 を叩かない。押すのは rclone（npm の外）

## Biome

`biome.json`。`.astro` と `.svelte` を見るため `html.experimentalFullSupportEnabled` をオン。Markdown / MDX の本文は対象外。

```sh
npm run check    # astro check → svelte-check → biome check
npm run format   # biome check --write .
```

## コマンド

```sh
npm install
npm run dev
npm run build
npm run preview
npm run check
```

`dev` と `build` は、先に `npm run check` を走らせる。通らなければサーバも `dist` も出さない。check は起動時（または build 時）に一度だけ。ファイルを直すたびに裏で回り続けるわけではない。

## デプロイ

詳細は `docs/デプロイ設定.md`。`main` への push で Cloudflare の Workers Builds が `npm run build` し、`npx wrangler deploy` が `dist` を Workers へ上げる。上げるのは `dist` だけ。GitHub Actions は使わない。

Node の版は `.nvmrc` から拾われる。`engines.node` は下限なので、実際に使う版はこちらで決まる。

展示の絵はこの流れに乗らない。原本は R2 で、押すのは手元から rclone。ビルド環境には実体が無いので、`dist/images/` に入るのは `site` だけになる。
