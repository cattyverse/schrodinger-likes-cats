# Schrödinger Likes Cats

技術要件

何を作るかは `docs/企画書.md`。この文書は、それをどう持つかだけ書く。画面の並びは企画書。ここでは、その部品がどのファイルかだけ対にする。幅・密度・カードの中の書き方は `docs/レスポンシブ.md`。

名前: ファイルとフォルダは小文字開始。slug（contents / lab のフォルダ、URL、`images/` の下）は kebab。`schrodingers-cat`、`monty-hall`。

## 1. 方針

静的生成が前提。サーバー処理は持たない。画面の基準は 360 CSS px（いまのスマホの下限の本体）。そこで組んだ形を、広くなっても組み替えない。320 はレガシー。壊れなければよい。PC は最大幅と中央寄せで違和感を出さない程度。PC 向けの別レイアウトは今はやらない（`docs/レスポンシブ.md`）。

人が開くページは、いま次のとおり。トップ `/`、展示の詳細 `/{slug}`、404。部屋の見方はパスを増やさず、トップのクエリ `?catalog=` と `?tag=` で切り替える。`?catalog=` だけでも可。登録日の降順で全件見るのは `?order=published`（ナビの新着）。実験場 `/lab`、について `/about` は未着手。見た目を連続させる候補は Astro View Transitions。初回公開の必須にはしない。カタログの棚では、同じトップのまま `history.pushState` で列を入れ替える。

無いアドレスは 404 専用画面。`src/pages/404.astro` → 公開ルートの `404.html`。Workers の静的アセットが、このサイトの下にファイルが無いときこれを返す（`not_found_handling` は `404-page`）。サーバの 302 で `/schrodingers-cat` へ付け替えない。中身はシュレ猫の遊びだけ（同じ `play.ts`。説明・関連は出さない）。窓枠は付ける。サイトマップにもナビにも出さない。遊びの HTML は `play.astro` をページへ埋め込む（カード用の partial は fetch しない）。

カードの切れ端はページではない。Astro の page partial（`export const partial = true`）で、`/partial/...` に HTML だけ出す。サイトマップにも窓枠にも出さない。直打ちすればファイルは返る。

公開先は Cloudflare Workers の静的アセット。ドメインは `cattyverse.com`、Route は `cattyverse.com/schrodinger-likes-cats` と `cattyverse.com/schrodinger-likes-cats/*` の 2 本（`*` は直前の `/` を要求するので、末尾スラッシュ無しは別に要る）。基底は `/schrodinger-likes-cats/`。取得 URL も `/?catalog=` も `/?tag=` も、この前綴りを付ける（`import.meta.env.BASE_URL`）。`cattyverse.com/` そのものは空けておく。このサイトは CATC が置いたキャンバスのひとつで、増えたら隣に足す。

画像は `src/public/images/{slug}/` に置く。slug は `contents/` または `lab/` のフォルダ名。`schrodingers-cat` なら `src/public/images/schrodingers-cat/`。`monty-hall` を足したら `src/public/images/monty-hall/`。ロゴなどは `src/public/images/site/`（slug が `site`）。この並びは手元の話。リポジトリに入るのは `site` だけで、展示の絵は `.gitignore` にある。原本は R2（下記）。ソースからの `import` や相対パスでファイルを取るのは禁止。JSON に書くのはファイル名だけ。4コマのコマ名は JSON にもソースにも書かない。

URL は `imageUrl(slug, ファイル名)`（`scripts/url.ts`）。slug は作らない。一覧はカタログの slug。partial の glob が `contents/*/play.astro` のフォルダ名を `params.slug` にする。遊びの絵は `imageUrl(slug, "play/box.svg")` など。関連は `related.json` のフォルダ名。ロゴは `"site"`。4コマの1枚目は `imageUrl(slug, "frames/frame1.svg")`。`play.ts` では呼ばない。HTML に載った `src` を使う。JSON の名前はそのまま。

基底はこの関数の中で三つに分かれる。`site` は同じオリジンの `BASE_URL + images/site/`。それ以外は、本番が `https://assets.cattyverse.com/schrodinger-likes-cats/{slug}/`、開発が `BASE_URL + images/{slug}/`（手元の `publicDir`）。呼ぶ側は分岐を知らない。画像ホストを変えるときも、直すのはここだけ。

4コマは `{slug}/frames/frame1.svg` から連番（SVG）。番号は1桁。枚数は `meta.json` の `frames`。フォルダは数えない（数はリポジトリ側で分かる）。ビルドは R2 を見ない。間隔（ミリ秒）は同じ `meta.json` の `interval`。見せている時間。押し上げはそのあと。`components/framesTemplate.svelte` がコマを全部 DOM に置く。`src` は最初から付ける。1枚目はタイトル。

`meta.frames` は手で書く。R2 の実体とずれても、ビルドは気づかない。取れなかったコマは `imageUrl("site", "missing.svg")` に差し替えて進む。そこで止めない。`missing.svg` はリポジトリ側なので、これ自体は必ずある。

切り替えの長さは全展示共通（仮）。次コマへは下から押し上げ 0.3 秒。タイトルが1枚目。そのあと絵。最後の次も同じ押し上げでタイトルに戻る。白待ちはしない。

画面に出す絵は SVG（よくあるイラスト。ロゴ、猫、箱、4コマ）。`viewBox` を付ける。サイズ違いは作らない。写真レベルだけ WebP 一枚（カード最大幅の 2 倍くらい）。OGP は PNG（1200×630。SNS の大きいプレビュー用。標準が変わったら変える）。SVG はクローラが使えない。`meta.image` は OGP と関連用なので、こちらも同じ PNG。GIF やアニメ WebP は持たない。

展示の絵の原本は Cloudflare R2。リポジトリには置かない。バケットは `cattyverse` 全体で共有し、キーは `schrodinger-likes-cats/{slug}/{ファイル名}`。配信は R2 のカスタムドメイン `assets.cattyverse.com`。`Cache-Control` は 1 日。パージの仕組みは持たない。絵を差し替えたら、行き渡るまで最大 1 日待つ。開発は手元を見るので、待つのは本番の確認だけ。

Worker は通さない。通すと静的アセットではなくなり、無料枠の 100,000 リクエスト/日 を食う。枯渇したとき、画像だけが 429 になって静的配信に落ちない。R2 のカスタムドメインは Cloudflare が直接返すので、この枠にあたらない。

押すのは手元から片方向（rclone）。ビルドからは押さない。外を手で直さない。ビルド環境に画像が無いので、`dist/images/` に入るのは `site` だけ。ビルドは R2 に触れず、トークンも要らない。R2 が落ちてもビルドは通る。

R2 にはバージョニングが無い。上書きも削除も戻せない。控えは手元のディスクだけで、それ以上は取らない。上書きする前に別名で残すのは自分の責任。

ロゴなど使い回す部品（slug が `site`）はリポジトリに残す。R2 へは出さない。全ページに出るので、上げ忘れると窓枠ごと壊れる。`missing.svg` も、それ自体が欠けたら意味が無いので同じ側。試し描きを積み上げるのは展示の絵であって、これらではない。

展示の絵は履歴に積まない。R2 が原本なので、何度描き直してもリポジトリは重くならない。Git が版を持つのは `site` の部品だけ。こちらは滅多に変わらないので、1枚を仕上げてから 1 コミットでよい。

枠は次のとおり。R2 はストレージ 10 GB、書き込み 100 万/月、読み取り 1000 万/月まで無料。転送（egress）は常に無料。Workers の静的アセットはリクエスト無制限で、1 デプロイ 20,000 ファイル、1 ファイル 25 MiB。帯域の上限は無い。SVG 主体のこのサイトは、どれにも当たらない。

共通の CSS も同じ。`src/public/styles/`。取るのは `styleUrl`。キャンバスと文字は `global.css`、カードの枠は `card.css`。page partial には CSS が乗らないので、殻（index。lab は未着手）が `<link>` する。コンポーネントは import、切れ端は fetch、見た目の共通部分は静的 CSS。

ヘッダーは固定しない。2段目のリンク列は `overflow-x` で横スクロールし、項目が増えてもレイアウトを変えない。

## 2. 技術

- Astro
- MDX
- Svelte 5（contents の動き。`mount` / `unmount` は Svelte 5 の API）
- TypeScript 6（7 は Astro / Svelte が programmatic API に追いつくまで待つ）
- CSS
- Biome（整形と lint。Prettier / ESLint は使わない）
- Cloudflare Workers（静的アセット。Worker のコードは持たない）
- Cloudflare R2（展示の絵。`assets.cattyverse.com`）

コンポーネントは `components/`。import する。窓枠（`siteHeader`、`siteFooter`。joinPrompt / certificate は未着手）も、棚の型（`tagShelf`）も、詳細の型も同じ場所。切れ端は `pages/partial/`。fetch する。今出すのは遊びだけ。`contents/{slug}/play.astro` を glob して `/partial/{slug}/play/` に焼く。カードの遊びだけそれを fetch する。詳細と 404 は同じ `play.astro` を import する。カードは JSON（カタログ）から `scripts/feed.ts` が `components/cardTemplate.svelte` を `mount` する。4コマは `components/framesTemplate.svelte`。CSS は乗らない切れ端なので、カードの枠は `styles/card.css`。殻が `styleUrl` で `<link>` する。遊びの見た目と動きは `contents/{slug}/play.css` と `play.ts`。

ja にコンポーネントは置かない。MDX と、文言の JSON だけ。文言が無い MDX は置かない。その組はコンポーネントだけになる。

動きを差し込んだ HTML の `<script>` では起動しない。カードでは差し込むのはマークアップだけ。その根っこに対して Svelte の `mount` を呼ぶと動きが始まる。外すときは同じパッケージの `unmount` を呼ぶ。外さないと、画面から消えても裏で動き続ける。詳細と 404 は `play.astro` をページに埋め、同じ `play.ts` を `mount` する。動きの本体は一つ。ソースの HTML も `play.astro` 一つ。

```
components/（siteHeader・siteFooter・tagShelf・detailTemplate・playTemplate・cardTemplate・framesTemplate）
contents/{slug}/play.astro
contents/{slug}/detail.astro
contents/{slug}/meta.json
contents/{slug}/ja（introduction.json と MDX）
tags/ja/tags.json
site/ja（ui.json・nav.json。about.mdx は未着手）
src/public/images/site/・src/public/styles/（そのまま公開）
  ↓
Astro build（page partial の glob が contents/*/play.astro をなめる）
  ↓
HTML ＋ /partial/{slug}/play/ ＋ /images/site/… ＋ /styles/… ＋ _astro（JS）
  ↓
Cloudflare Workers（静的アセット。BASE_URL 付き）


R2 の schrodinger-likes-cats/{slug}/（展示の絵。4コマは frames/frame1.svg から連番）
  ↓
assets.cattyverse.com（R2 のカスタムドメイン。ビルドもデプロイも通らない）
```

いま公開するのは日本語だけ。公開 URL は当面 `/{slug}`（基底のあと）。将来は同じ型で `ja` の隣に `en` を足す。

## 3. 画面とファイル



### カードと、詰める側

カードの枠は `components/cardTemplate.svelte`。一覧がカタログ（introduction と meta）から `mount` する。HTML 文字列では組まない。fetch しない。

```
説明
中身              4コマ。components/framesTemplate.svelte。タイトルが1枚目。開いても残す
タグ              chip。→ /?catalog=&tag=
遊び              開いたとき。/partial/{slug}/play/ を fetch
解説              開いたとき。ラベルとページ名のリンク
More              カードの一番下。二重 V を四角で囲う。下に足す／閉じる。高さは伸び縮み
```

| もの | 詰める側 | 詰めるもの |
| --- | --- | --- |
| `components/cardTemplate.svelte` | `scripts/feed.ts` が `mount` | カタログの title、description、tag id |
| `components/framesTemplate.svelte` | カタログの `frames` / `interval` | 先頭はタイトル。そのあと `frame1.svg` から連番。番号は1桁 |
| `contents/{slug}/play.astro` | `pages/partial/[slug]/play.astro` が glob。詳細・404 は同じファイルを import | 遊びの HTML。カードは fetch。詳細・404 はページに埋め込む |
| `components/tagShelf.svelte` | `scripts/feed.ts` が `?catalog=` のとき `mount` | 名称、説明、配下のタグ。いまの `tag=` は押下中。文言と部屋は `ja/tags.json` |
| `components/detailTemplate.astro` | `contents/{slug}/detail.astro` | introduction、meta、遊び（import）、`detail.mdx`、related |


`pages/index.astro` は殻。ビルド時に contents をなめて一覧を JS の配列としてページに埋め込む。実行時は `scripts/feed.ts` がそれを見て `cardTemplate.svelte` を `mount` する。`contents/*/card.astro` は置かない。`pages/[slug].astro` は対応する `detail.astro`（完成ページ。partial ではない）。詳細の遊びは `play.astro` を import して HTML に載せる。`pages/lab.astro` / `pages/about.astro` は未着手。トップの一覧には lab を出さない。

切れ端は遊びだけ。展示の数だけファイルは増えない。`pages/partial/[slug]/play.astro` が `contents/*/play.astro` を glob する。出る URL は `/partial/{slug}/play/`。

`export const partial = true`。`<html>` も scoped CSS も script も付けない（Astro の page partial）。カードの枠の CSS は `styles/card.css`。殻が `styleUrl` で `<link>` する。遊びは差し込み後に `mount`。カードも `mount`。4コマの切り替えは CSS。keyframes は slug ごとに `style#frames-anim` へ一度だけ書く。`mount` のたびに JS も枠の CSS も増えない。

棚の上は `?catalog=` のとき `tagShelf` を `mount`。名称、説明、配下のタグ。カードのタグは `cardTemplate` が chip を書く。`?catalog=&tag=`。同じトップ上では遷移せず列を入れ替える。

### 窓枠（全ページ）

```
[ ロゴ  サイト名 ]                 siteHeader 1段目。押すとクエリ無しのトップ。ui.json の name
[ last updated  ビルド日 ]         ロゴの下。サイトの最終更新。日付だけ。時刻は出さない
[ 実験場  about  新着  #クイズ  #数学  #科学 ] siteHeader 2段目。部屋は nav.json、カタログは tags.json
```

詳細以外の末尾に siteFooter（同じ logo。トップへ）。詳細にはフッターを置かない。404 には置く。固定しない。

最終更新はビルド時刻の日付。`siteHeader` の前処理で `new Date()` を取り、HTML に焼く。訪問者側の時計は使わない（`<script>` の `new Date()` だと見る人の今日になる）。タイムゾーンは `Asia/Tokyo` に固定する。Workers Builds のマシンは UTC なので、固定しないと日付が一日ずれることがある。`astro dev` ではリロードのたびに「今」になる。本番の日付は `astro build` の成果を見る。展示の `published` は出さない。デプロイのたびに進むので、展示を足したとき（または窓枠を直したとき）に上げる。

カタログの棚は `?catalog=` が付いたときだけ出す。名称、説明、配下のタグ。いまの `tag=` は押下中。

CSS: 白いキャンバスと共通の文字は `src/public/styles/global.css`、カードの枠は `card.css`（どちらも `styleUrl`）。`--card-max` は 864px（FHD の 45%）。page partial には CSS が乗らない。カードの枠は殻が `<link>` する。import したコンポーネント（ヘッダーなど）の見た目は、その `<style>` でよい。展示の遊びの見た目と動きは `contents/{slug}/` の `play.astro` / `play.css` / `play.ts`。fetch した HTML には CSS が乗らないので、カードでは `playTemplate` がその slug の `play.css` と `play.ts` を import する。詳細・404 は `play.astro` の import で CSS がページに乗る。Svelte のカード／4コマには `<style>` を置かない（`mount` のたびに増えない）。4コマの切り替えは `components/framesTemplate.svelte` が slug ごとの keyframes を `style#frames-anim` へ一度書く。

### 展示（トップ）`/` と棚 `/?catalog=`

同じ殻。`pages/index.astro`。

クエリなし: なめた配列を乱数する。その先頭へ `schrodingers-cat` を足す（配列に `lead` 欄は無い）。重複しないよう、乱数側からは外す。URL には残さない。リロードで変わる。タグ列は出さない。

`?catalog=`: その部屋。配下のどれかが `meta.tags` にある展示。`published` の降順。先頭に配下のタグを全部出す。

`?catalog=&tag=`: そのタグ。同じタグ列のまま、押したタグが押下中。同じトップ上で列を入れ替える。

`?order=published`: 全件を `published` の降順。シュレ猫の先頭固定はしない。タグ列は出さない。

同時に開くカードは何枚でもよい。別のカードを開いても、前のスロットは遊びのまま。状態は保存する。閉じるのはそのカードのトグルだけ。画面外でもカードは残す（仮想化しない）。並びは常に 1 列。`--card-max` 未満は全幅、以上は中央。余りはキャンバス。

### 索引 `/tags`

持たない。カタログはナビと棚の先頭。

### 詳細 `/{slug}`

`pages/[slug].astro` が `contents/` のフォルダ名をなめて、各 `/{slug}` の HTML を出す。ソースは `detail.astro` のまま。`pages/schrodingers-cat.astro` を展示の数だけ置く必要はない。ビルド成果は `schrodingers-cat/index.html`。遊びは `play.astro` を import して埋め込む。`play.ts` は `playTemplate`（`embedded`）が `mount` する。OGP を出す。

### 実験場 `/lab`

未着手。`pages/lab.astro` が開く予定。殻。ビルド時に lab をなめて一覧を埋め込む。カードはカタログから組み立てる。展示のカードとは別。トグルもタグも詳細へも無い。乱数もしない。順は `published` の降順。

```
タイトル
一文
中身スロット     HTML。文字でも画像でも、その組み合わせでもよい
```

`lab/{slug}/card.astro` が `labCardTemplate` を使い、スロットに HTML を入れる予定。例: `lab/monty-hall/`。育って展示になったら `contents/` へ移す。

### について `/about`

未着手。窓枠＋ `site/ja/about.mdx`。JoinPrompt と Certificate を足す予定。

### 404 専用画面 `404.html`

`pages/404.astro`。無いアドレスの着地。詳細 `/{slug}` ではない。Workers の静的アセットが、このサイトの下にファイルが無いときこれを返す。HTTP は 404 のまま。URL は打ち込んだまま。

中身は `contents/schrodingers-cat` の遊びだけ。`play.astro` を埋め込んで `play.ts` を `mount` する。説明・関連は出さない。窓枠は付ける（フッターあり）。

## 6. 一覧の動き

殻だけ先に出す。トップは埋め込みの contents 一覧を使う。lab は見ない。

順: クエリなしは乱数した配列の先頭へ `schrodingers-cat` を足す（乱数側からは外す）。`?catalog=` は配下のどれか、`?tag=` はそのタグ。`published` の降順。棚は名称、説明、配下のタグ。同じトップ上でタグを押すと列を入れ替える（初回の 0.5 秒待ちはしない）。`?order=published` は全件の新しい順。棚は出さない。同じトップ上なら新着への切替も遷移しない。

足し方は仮想化しない。画面外のカードを外さない。一度足した DOM は残す。開いた遊びも、カードの高さが展示ごとに違っても残る。トグルで他を閉じない。

出す量は行数。列は常に 1 なので、枚数＝行数。カードが無い初回は 12（残数が足りなければその分）。出してから最後のカードで余りを測り、まだ窓が埋まっていれば `max(12, ceil(必要行 / 12) * 12)` で足す。追加も同じ式。最低 12 行。足りなければ 24, 36, 48…。出した行数は、カタログの端を除き常に 12 の倍数。空のカード高さを CSS px で見積もらない。

追加は、一覧の末尾が見えたとき。ホイールでもバーでもキーでもよい。末尾に番兵を置き、それが窓に入ったら足す。着く前には走らない。走ったらすぐ末尾に少し余白を取り、ローディングを出す。見た目はよくある回るやつ。そのあいだに、この回の追加分をカタログから組み立てる。全部揃ってから一気に足す。途中経過では足さない。画像のロードは待たない（HTML が入った時点で1枚目の取得は始まる）。組み立てが先に終わっても、ローディングは最低 0.5 秒出す。ローディングと余白は、足したら外す。取りの途中にもう一度スクロールしても、二回目は走らせない。カタログの残りが足りなければ残りだけ足す。

並び: 常に 1 列。`--card-max`（864px。FHD の 45%）未満は全幅、以上は中央。`margin-inline: auto`。余りはキャンバス。`@media` でも機種名でもない。横持ち専用にはしない。列数を JS で読まない。リサイズや縦横の切り替えで列は変わらない。カード幅は変わりうる（全幅 ↔ 最大）。画面外のカードは `unmount` しない。カタログやタグを入れ替えるときだけ外して組み直す。スクロール位置を 12 行グループで戻すのは後回し。書き方は `docs/レスポンシブ.md`。

この回で足す上限は、追加の回数と、この一覧の展示の残り。初回のあと、増やせるのは 20 回（仮）。1 回の量は上の式（最低 12 行、必要なら 12 の倍数）。判定は足すときだけ。幅が変わっても回数は戻さない。既にあるカードは外さない。

フッターは、足した結果この一覧の残りが 0 のとき、または 20 回目を足したとき。20 回目にはすでにフッターがある。21 回目のスクロールは無い。ローディングのあいだは出さない。揃って足したあとに出す。初回で全部出ても残り 0 なのでフッター。`?catalog=` も `?tag=` も同じで、その部屋／タグの展示が上限。カタログ全体ではない。トップの乱数は URL に残さないので、リロードで別の先頭になりうる。棚と lab は順が固定。

4コマの枠は比を先に取る（画像待ちでカードが伸びない）。タイトルの 1 行／2 行は、出したカードのレイアウトに任せる。覚えない。上に戻っても、残っている DOM なので飛ばない。

足したカードの中身は4コマ。`components/framesTemplate.svelte`（カードの `mount` と一緒。切り替え自体は CSS）。

トグルはカードごと。他のカードは触らない。More で extra を開く。4コマは残す。下に遊びと解説を足す。高さは伸び縮みする。

遊びを出すとき（`playTemplate.svelte`）:

カード:

1. extra が開くまで待つ（`inert` が外れる）
2. `/partial/{slug}/play/` を `fetch` する
3. 根っこへ入れる
4. その slug の `play.ts` を import して `mount`（`play.css` もここで乗る）

詳細・404（`embedded`）:

1. `play.astro` はページの HTML に既にある。fetch しない
2. `[data-play-root]` 内の遊びへ `play.ts` を `mount`
3. 島を動かすため、隠し `span.play-bind` を同じ根っこに置く。空のコンポーネントだと島が動かない

Windows では `import.meta.glob` のキーが `\` になりうる。`play.ts` / `play.css` の照合は `/` に揃えてから `endsWith` する。

HTML 内の script は実行しない。Svelte のコンポーネントは `unmount` で外す。遊びの `play.ts` の `mount` は止め関数を返す。`playTemplate` がそれを呼ぶ。DOM を捨てるだけでは、ドラッグの処理が裏に残ることがある。入れ替え前に必ず外す。

`play.ts` の動きは詳細の遊びと同じもの。ソースの HTML も `play.astro` 一つ。カードだけ partial を取る。詳細と 404 は同じファイルを import する。

4コマ（`components/framesTemplate.svelte`）:

1. コマは全部 DOM に置く。`src` は最初から付ける（`loading="lazy"`）
2. 先頭はタイトル。そのあと `frame1.svg` から連番
3. 切り替えは CSS の keyframes。間隔は meta の `interval`。押し上げ 0.3 秒はそのあと
4. 次へは下からせりあげる。最後の次も同じ押し上げでタイトルに戻る。白待ちはしない
5. 取れなかったコマは `imageUrl("site", "missing.svg")` に差し替えて進む。そこで止めない
6. keyframes は slug ごとに `style#frames-anim` へ一度。カードの中に `<style>` は置かない（`mount` のたびに CSS が増えない）

箱を持ち上げるなどの本番は遊びと詳細だけ。4コマにキャプションは付けない。代替テキストや `prefers-reduced-motion` は後回し。

`/lab` は未着手。足したら殻。埋め込みの lab 一覧からカードを組み立てる。トグルも乱数も無い。順は `published` の降順。足し方・残し方・上限・幅の収まりはトップと同じ。

## 7. 後回しにしてよい技術

- View Transitions
- 関連の自動提案。表示時には使わない
- 言語パス（`/en/...`）と言語切替
- 証書の見た目の詰め
- 4コマの a11y（代替テキスト、`prefers-reduced-motion`）
- 4コマの切り替え時間の詰め（押し上げ 0.3 秒は仮）。画面外では止めるか
- 一覧の追加 20 回の詰め。`--card-max` は 864px。画面外 DOM を外す仮想化は、この上限で足りなくなってから
- PC 向けの使いやすさ（複数列、サイドバー、ホバー前提の操作）
- 12 行グループでスクロール位置を戻す（幅で高さが変わるので、目安にする）
- サイトマップ作製: `@astrojs/sitemap`。`site` と `base` は既にある。ビルドで `sitemap-index.xml` が出る。`/partial/` と `404.html` は載せない。Jekyll の `jekyll-sitemap` は使わない
- Search Console 登録: URL プレフィックス `https://cattyverse.com/schrodinger-likes-cats/`。所有権確認は HTML ファイル。ドメインを移したあとに一度だけ
- サイトマップ URL 送信: `https://cattyverse.com/schrodinger-likes-cats/sitemap-index.xml` を 1 回送る。デプロイのたびに ping はしない（廃止済み）
- 画像の CORS。`<img>` で出すだけなら要らない。遊びが SVG を canvas へ描いて読み出すようになったら、R2 側に足す
- R2 へ押す手順のスクリプト化。いまは rclone を手で叩く
