# Schrödinger Likes Cats

技術要件

何を作るかは `docs/企画書.md`。この文書は、それをどう持つかだけ書く。画面の並びは企画書。ここでは、その部品がどのファイルかだけ対にする。幅・密度・カードの中の書き方は `docs/レスポンシブ.md`。

名前: ファイルとフォルダは小文字開始。slug（contents / lab のフォルダ、URL、`images/` の下）は kebab。`schrodinger-cat`、`monty-hall`。

## 1. 方針

静的生成が前提。サーバー処理は持たない。画面の基準は 360 CSS px（いまのスマホの下限の本体）。そこで組んだ形を、広くなっても組み替えない。320 はレガシー。壊れなければよい。PC は最大幅と中央寄せで違和感を出さない程度。PC 向けの別レイアウトは今はやらない（`docs/レスポンシブ.md`）。

人が開くページは次だけ。展示の詳細 `/{slug}`、索引 `/tags`、実験場 `/lab`、について `/about`。個別のタグ見方はパスを増やさず、トップのクエリ `?tag=` で切り替える。見た目を連続させる候補は Astro View Transitions。初回公開の必須にはしない。

無いアドレスは 404 専用画面。`src/pages/404.astro` → 公開ルートの `404.html`。Workers の静的アセットが、このサイトの下にファイルが無いときこれを返す（`not_found_handling` は `404-page`）。サーバの 302 で `/schrodinger-cat` へ付け替えない。中身はシュレ猫の遊びだけ（同じ `play.ts`。説明・関連は出さない）。窓枠は付ける。サイトマップにもナビにも出さない。

カードの切れ端はページではない。Astro の page partial（`export const partial = true`）で、`/partial/...` に HTML だけ出す。サイトマップにも窓枠にも出さない。直打ちすればファイルは返る。

公開先は Cloudflare Workers の静的アセット。ドメインは `cattyverse.com`、Route は `cattyverse.com/schrodinger-likes-cats` と `cattyverse.com/schrodinger-likes-cats/*` の 2 本（`*` は直前の `/` を要求するので、末尾スラッシュ無しは別に要る）。基底は `/schrodinger-likes-cats/`。取得 URL も `/?tag=` も、この前綴りを付ける（`import.meta.env.BASE_URL`）。`cattyverse.com/` そのものは空けておく。このサイトは CATC が置いたキャンバスのひとつで、増えたら隣に足す。

画像は `src/public/images/{slug}/` に置く。slug は `contents/` または `lab/` のフォルダ名。`schrodinger-cat` なら `src/public/images/schrodinger-cat/`。`monty-hall` を足したら `src/public/images/monty-hall/`。ロゴなどは `src/public/images/site/`（slug が `site`）。この並びは手元の話。リポジトリに入るのは `site` だけで、展示の絵は `.gitignore` にある。原本は R2（下記）。ソースからの `import` や相対パスでファイルを取るのは禁止。JSON に書くのはファイル名だけ。4コマのコマ名は JSON にもソースにも書かない。

URL は `imageUrl(slug, ファイル名)`（`scripts/url.ts`）。slug は作らない。一覧はカタログの slug。partial の glob が `contents/*/play.astro` のフォルダ名を `params.slug` にする。`imageUrl(slug, "cat.svg")`。関連は `related.json` のフォルダ名。ロゴは `"site"`。4コマの1枚目は `imageUrl(slug, "frames/frame1.svg")`。`play.ts` では呼ばない。HTML に載った `src` を使う。JSON の名前はそのまま。

基底はこの関数の中で三つに分かれる。`site` は同じオリジンの `BASE_URL + images/site/`。それ以外は、本番が `https://assets.cattyverse.com/schrodinger-likes-cats/{slug}/`、開発が `BASE_URL + images/{slug}/`（手元の `publicDir`）。呼ぶ側は分岐を知らない。画像ホストを変えるときも、直すのはここだけ。

4コマは `{slug}/frames/frame1.svg` から連番（SVG）。番号は1桁。枚数は `meta.json` の `frames`。フォルダは数えない（数はリポジトリ側で分かる）。ビルドは R2 を見ない。間隔（ミリ秒）は同じ `meta.json` の `interval`。見せている時間。押し上げはそのあと。`components/framesTemplate.svelte` がコマを全部 DOM に置く。`src` は最初から付ける。1枚目はタイトル。

`meta.frames` は手で書く。R2 の実体とずれても、ビルドは気づかない。取れなかったコマは `imageUrl("site", "missing.svg")` に差し替えて進む。そこで止めない。`missing.svg` はリポジトリ側なので、これ自体は必ずある。

切り替えの長さは全展示共通（仮）。次コマへは下から押し上げ 0.3 秒。タイトルが1枚目。そのあと絵。最後の次も同じ押し上げでタイトルに戻る。白待ちはしない。

画面に出す絵は SVG（よくあるイラスト。ロゴ、猫、箱、4コマ）。`viewBox` を付ける。サイズ違いは作らない。写真レベルだけ WebP 一枚（カード最大幅の 2 倍くらい）。OGP は PNG（1200×630。SNS の大きいプレビュー用。標準が変わったら変える）。SVG はクローラが使えない。`meta.image` は OGP と関連用なので、こちらも同じ PNG。GIF やアニメ WebP は持たない。

展示の絵の原本は Cloudflare R2。リポジトリには置かない。バケットは `cattyverse` 全体で共有し、キーは `schrodinger-likes-cats/{slug}/{ファイル名}`。配信は R2 のカスタムドメイン `assets.cattyverse.com`。`Cache-Control` は 1 日。パージの仕組みは持たない。絵を差し替えたら、行き渡るまで最大 1 日待つ。開発は手元を見るので、待つのは本番の確認だけ。

Worker は通さない。通すと静的アセットではなくなり、無料枠の 100,000 リクエスト/日 を食う。枯渇したとき、画像だけが 429 になって静的配信に落ちない。R2 のカスタムドメインは Cloudflare が直接返すので、この枠にあたらない。

押すのは手元から片方向（rclone）。ビルドからは押さない。外を手で直さない。ビルド環境に画像が無いので、`dist/images/` に入るのは `site` だけ。ビルドは R2 に触れず、トークンも要らない。R2 が落ちてもビルドは通る。

R2 にはバージョニングが無い。上書きも削除も戻せない。控えは手元のディスクだけで、それ以上は取らない。上書きする前に別名で残すのは自分の責任。

ロゴなど使い回す部品（slug が `site`）はリポジトリに残す。R2 へは出さない。全ページに出るので、上げ忘れると窓枠ごと壊れる。`missing.svg` も、それ自体が欠けたら意味が無いので同じ側。試し描きを積み上げるのは展示の絵であって、これらではない。

展示の絵は履歴に積まない。R2 が原本なので、何度描き直してもリポジトリは重くならない。Git が版を持つのは `site` の部品だけ。こちらは滅多に変わらないので、1枚を仕上げてから 1 コミットでよい。

枠は次のとおり。R2 はストレージ 10 GB、書き込み 100 万/月、読み取り 1000 万/月まで無料。転送（egress）は常に無料。Workers の静的アセットはリクエスト無制限で、1 デプロイ 20,000 ファイル、1 ファイル 25 MiB。帯域の上限は無い。SVG 主体のこのサイトは、どれにも当たらない。

共通の CSS も同じ。`src/public/styles/`。取るのは `styleUrl`。キャンバスと文字は `global.css`、カードの枠は `card.css`。page partial には CSS が乗らないので、殻（index / lab）が `<link>` する。コンポーネントは import、切れ端は fetch、見た目の共通部分は静的 CSS。

ヘッダーは固定しない。2段目のリンク列は `overflow-x` で横スクロールし、項目が増えてもレイアウトを変えない。

## 2. 技術

- Astro
- MDX
- Svelte 5（contents の動き。`mount` / `unmount` は Svelte 5 の API）
- TypeScript 6（7 は Astro / Svelte が programmatic API に追いつくまで待つ）
- CSS
- Biome（整形と lint。Prettier / ESLint は使わない）
- Cloudflare Workers（静的アセット。Worker のコードは持たない）
- Cloudflare R2（展示の絵。`assets.cattyverse.com`）

コンポーネントは `components/`。import する。窓枠（`siteHeader`、`siteFooter`、`joinPrompt`、`certificate`）も、索引の型（`tagTemplate`）も、詳細・lab の型も同じ場所。切れ端は `pages/partial/`。fetch する。今出すのは遊びだけ。`contents/{slug}/play.astro` を glob して `/partial/{slug}/play/` に焼く。カードは JSON（カタログ）から `scripts/feed.ts` が `components/cardTemplate.svelte` を `mount` する。4コマは `components/framesTemplate.svelte`。CSS は乗らない切れ端なので、カードの枠は `styles/card.css`。殻が `styleUrl` で `<link>` する。

ja にコンポーネントは置かない。MDX と、文言の JSON だけ。文言が無い MDX は置かない。その組はコンポーネントだけになる。

動きを差し込んだ HTML の `<script>` では起動しない。差し込むのはマークアップだけ。その根っこに対して `mount` を呼ぶと動きが始まる。外すときは `unmount`。外さないと、画面から消えても裏で動き続ける。詳細も 404 も、同じ `/partial/{slug}/play/` を取って `mount` する。動きの本体は一つ。

```
components/（siteHeader・tagTemplate・detailTemplate・labCardTemplate）
contents/{slug}/play.astro
contents/{slug}/detail.astro
contents/{slug}/meta.json
contents/{slug}/ja（introduction.json と MDX）
contents/{slug}/parts
tags/tag.astro・tags.json
tags/ja/tag.json
lab/{slug}/card.astro
lab/{slug}/ja（introduction.json と本文）
site/ja（短いラベル、について）
src/public/images/site/・src/public/styles/（そのまま公開）
  ↓
Astro build（page partial の glob が contents/*/play.astro をなめる）
  ↓
HTML ＋ /partial/{slug}/play/ ＋ /images/site/… ＋ /styles/… ＋ _astro（JS）
  ↓
Cloudflare Workers（静的アセット。BASE_URL 付き）


R2 の schrodinger-likes-cats/{slug}/（展示の絵。4コマは frames/frame1.svg から連番）
  ↓
assets.cattyverse.com（R2 のカスタムドメイン。ビルドもデプロイも通らない）
```

いま公開するのは日本語だけ。公開 URL は当面 `/{slug}`（基底のあと）。将来は同じ型で `ja` の隣に `en` を足す。

## 3. 画面とファイル



### カードと、詰める側

カードの枠は `components/cardTemplate.svelte`。一覧がカタログ（introduction と meta）から `mount` する。HTML 文字列では組まない。fetch しない。

```
説明
中身              4コマ。components/framesTemplate.svelte。タイトルが1枚目。開いても残す
タグ              chip。→ /?tag=
遊び              開いたとき。/partial/{slug}/play/ を fetch
解説              開いたとき。ラベルとページ名のリンク
More              カードの一番下。二重 V を四角で囲う。下に足す／閉じる。高さは伸び縮み
```

| もの | 詰める側 | 詰めるもの |
| --- | --- | --- |
| `components/cardTemplate.svelte` | `scripts/feed.ts` が `mount` | カタログの title、description、tag id |
| `components/framesTemplate.svelte` | カタログの `frames` / `interval` | 先頭はタイトル。そのあと `frame1.svg` から連番。番号は1桁 |
| `contents/{slug}/play.astro` | `pages/partial/[slug]/play.astro` が glob | 遊びの HTML。詳細もここから取る |
| `components/tagTemplate.astro` | `tags/tag.astro` | mode と id。文言は `tag.json`、木は `tags.json` |
| `components/detailTemplate.astro` | `contents/{slug}/detail.astro` | introduction、meta、遊び、`detail.mdx`、related |
| `components/labCardTemplate.astro` | `lab/{slug}/card.astro` | introduction、中身スロットの HTML |


`pages/index.astro` は殻。ビルド時に contents をなめて一覧を JS の配列としてページに埋め込む。実行時は `scripts/feed.ts` がそれを見て `cardTemplate.svelte` を `mount` する。`contents/*/card.astro` は置かない。`pages/[slug].astro` は対応する `detail.astro`（完成ページ。partial ではない）。詳細の遊びは `/partial/{slug}/play/` から取る。`pages/tags.astro` は `tags.json` をなめ、各ノードを `tag.astro`（mode=folder）で出す。`pages/lab.astro` も殻。ビルド時に lab をなめて同じ形で埋め込む。トップの一覧には lab を出さない。

切れ端は遊びだけ。展示の数だけファイルは増えない。`pages/partial/[slug]/play.astro` が `contents/*/play.astro` を glob する。出る URL は `/partial/{slug}/play/`。

`export const partial = true`。`<html>` も scoped CSS も script も付けない（Astro の page partial）。カードの枠の CSS は `styles/card.css`。殻が `styleUrl` で `<link>` する。遊びは差し込み後に `mount`。カードも `mount`。4コマの切り替えは CSS。keyframes は slug ごとに `style#frames-anim` へ一度だけ書く。`mount` のたびに JS も枠の CSS も増えない。

棚の上は `tag.astro` を今の id で 1 つ（mode=shelf）。パンくずはテンプレートが祖先を辿る。カードのタグは id ごとに mode=chip。

### 窓枠（全ページ）

```
[ ロゴ              タグ検索 ] siteHeader 1段目。アイコン行。logo。ui.json。→ /tags
[ ビルド日 ]                   ロゴの下。サイトの最終更新。日付だけ。時刻は出さない
[ 実験場  について  … ]     siteHeader 2段目。nav.json
```

詳細以外の末尾に siteFooter（同じ logo。トップへ）。詳細にはフッターを置かない。404 には置く。固定しない。

最終更新はビルド時刻の日付。`siteHeader` の前処理で `new Date()` を取り、HTML に焼く。訪問者側の時計は使わない（`<script>` の `new Date()` だと見る人の今日になる）。タイムゾーンは `Asia/Tokyo` に固定する。Workers Builds のマシンは UTC なので、固定しないと日付が一日ずれることがある。`astro dev` ではリロードのたびに「今」になる。本番の日付は `astro build` の成果を見る。展示の `published` は出さない。デプロイのたびに進むので、展示を足したとき（または窓枠を直したとき）に上げる。

タグ検索の中身（その場で絞るか）は後で詰める。いまは `/tags` へ行く。

CSS: 白いキャンバスと共通の文字は `src/public/styles/global.css`、カードの枠は `card.css`（どちらも `styleUrl`）。`--card-max` は 864px（FHD の 45%）。page partial には CSS が乗らない。殻が `<link>` する。import したコンポーネント（ヘッダーなど）の見た目は、その `<style>` でよい。fetch する切れ端は遊び。カードの枠は静的 CSS。Svelte のカード／4コマには `<style>` を置かない（`mount` のたびに増えない）。展示の遊びの見た目は `parts/`。4コマの切り替えは `components/framesTemplate.svelte` が slug ごとの keyframes を `style#frames-anim` へ一度書く。

### 展示（トップ）`/` とタグの棚 `/?tag=`

同じ殻。`pages/index.astro`。

クエリなし: なめた配列を乱数する。その先頭へ `schrodinger-cat` を足す（配列に `lead` 欄は無い）。重複しないよう、乱数側からは外す。URL には残さない。リロードで変わる。

クエリあり: そのタグ（`meta.tags` にその id がある展示）、`published` の降順。子タグのボタン列は出さない。配下の収集はしない。親の棚にも出したい展示は、親の id も `meta.tags` に付ける。

同時に開くカードは何枚でもよい。別のカードを開いても、前のスロットは遊びのまま。状態は保存する。閉じるのはそのカードのトグルだけ。画面外でもカードは残す（仮想化しない）。並びは常に 1 列。`--card-max` 未満は全幅、以上は中央。余りはキャンバス。

### 索引 `/tags`

`pages/tags.astro` が `tags.json` の親から `tag.astro`（mode=folder）を並べる。下に開く。個別のタグ用パスは作らない。

### 詳細 `/{slug}`

`pages/[slug].astro` が `contents/` のフォルダ名をなめて、各 `/{slug}` の HTML を出す。ソースは `detail.astro` のまま。`pages/schrodinger-cat.astro` を展示の数だけ置く必要はない。ビルド成果が `schrodinger-cat.html`（または `schrodinger-cat/index.html`）になる。遊びは `/partial/{slug}/play/` から取る。OGP を出す。

### 実験場 `/lab`

`pages/lab.astro` が開く。殻。ビルド時に lab をなめて一覧を埋め込む。カードはカタログから組み立てる。展示のカードとは別。トグルもタグも詳細へも無い。乱数もしない。順は `published` の降順。

```
タイトル
一文
中身スロット     HTML。文字でも画像でも、その組み合わせでもよい
```

`lab/{slug}/card.astro` が `labCardTemplate` を使い、スロットに HTML を入れる。例: `lab/monty-hall/`。育って展示になったら `contents/` へ移す。

### について `/about`

窓枠＋ `site/ja/about.mdx`。JoinPrompt と Certificate を足す。

### 404 専用画面 `404.html`

`pages/404.astro`。無いアドレスの着地。詳細 `/{slug}` ではない。Workers の静的アセットが、このサイトの下にファイルが無いときこれを返す。HTTP は 404 のまま。URL は打ち込んだまま。

中身は `contents/schrodinger-cat` の遊びだけ。`/partial/schrodinger-cat/play/` から取って `play.ts` を `mount` する。説明・関連は出さない。窓枠は付ける（フッターあり）。

### dist/

出力は `dist/` 直下ではない。`outDir` を `./dist/schrodinger-likes-cats` にして、URL の階層とフォルダの階層を一致させる。Workers の静的アセットは、リクエストのパスをアセットのディレクトリにそのまま当てる。前綴りを剥がさない。`base` は Astro が書く URL を変えるだけなので、出力側も同じ形にしておかないと `dist/schrodinger-likes-cats/index.html` を探して見つけられない。GitHub Pages が前綴りを剥がしていたので、そこだけ振る舞いが違う。

`wrangler.jsonc` の `assets.directory` は `./dist`（`dist/schrodinger-likes-cats` ではない）。二重に潜ると `schrodinger-likes-cats/schrodinger-likes-cats/` を見にいく。

`build.format` は directory なのでページは `…/index.html`。`404.astro` は `404.html`。`not_found_handling` はパスの区切りを上へ辿って近い `404.html` を探すので、`/schrodinger-likes-cats/` の下で外したものはこの `404.html` に着く。

手元で `npm run build` すると `dist/schrodinger-likes-cats/images/` に展示の絵も入るが、`imageUrl` は本番の基底を返すので参照されない。混ざっても害はない。デプロイは Workers Builds からだけにする。

```
dist/
└ schrodinger-likes-cats/      ← Route のパスと同じ形。outDir がここ
   ├ index.html
   ├ 404.html
   ├ about/
   │  └ index.html
   ├ tags/
   │  └ index.html

   │  └ index.html
```

| 出力                           | 元                                                 | 使う画面               |
| ---------------------------- | ------------------------------------------------- | ------------------ |
| `/` の HTML に埋め込んだ配列 | `catalog.ts` がなめた introduction と meta | 順・絞り込み・カードの組み立て |
| `/partial/{slug}/play/`      | `contents/{slug}/play.astro`             | More と詳細と 404 の遊び       |

## 6. 一覧の動き

殻だけ先に出す。トップは埋め込みの contents 一覧を使う。lab は見ない。

順: クエリなしは乱数した配列の先頭へ `schrodinger-cat` を足す（乱数側からは外す）。クエリありは `meta.tags` にその id がある展示、`published` の降順。木は辿らない。

足し方は仮想化しない。画面外のカードを外さない。一度足した DOM は残す。開いた遊びも、カードの高さが展示ごとに違っても残る。トグルで他を閉じない。

出す量は行数。列は常に 1 なので、枚数＝行数。カードが無い初回は 12（残数が足りなければその分）。出してから最後のカードで余りを測り、まだ窓が埋まっていれば `max(12, ceil(必要行 / 12) * 12)` で足す。追加も同じ式。最低 12 行。足りなければ 24, 36, 48…。出した行数は、カタログの端を除き常に 12 の倍数。空のカード高さを CSS px で見積もらない。

追加は、一覧の末尾が見えたとき。ホイールでもバーでもキーでもよい。末尾に番兵を置き、それが窓に入ったら足す。着く前には走らない。走ったらすぐ末尾に少し余白を取り、ローディングを出す。見た目はよくある回るやつ。そのあいだに、この回の追加分をカタログから組み立てる。全部揃ってから一気に足す。途中経過では足さない。画像のロードは待たない（HTML が入った時点で1枚目の取得は始まる）。組み立てが先に終わっても、ローディングは最低 0.5 秒出す。ローディングと余白は、足したら外す。取りの途中にもう一度スクロールしても、二回目は走らせない。カタログの残りが足りなければ残りだけ足す。

並び: 常に 1 列。`--card-max`（864px。FHD の 45%）未満は全幅、以上は中央。`margin-inline: auto`。余りはキャンバス。`@media` でも機種名でもない。横持ち専用にはしない。列数を JS で読まない。リサイズや縦横の切り替えで列は変わらない。カード幅は変わりうる（全幅 ↔ 最大）。カードは `unmount` しない。スクロール位置はピクセルでは合わせない。見えていた 12 行グループ（`floor(先頭の行 / 12)`）の先頭が、おおよそ同じあたりに来るように戻す。幅で高さが変わるので、目安である。書き方は `docs/レスポンシブ.md`。

この回で足す上限は、追加の回数と、この一覧の展示の残り。初回のあと、増やせるのは 20 回（仮）。1 回の量は上の式（最低 12 行、必要なら 12 の倍数）。判定は足すときだけ。幅が変わっても回数は戻さない。既にあるカードは外さない。

フッターは、足した結果この一覧の残りが 0 のとき、または 20 回目を足したとき。20 回目にはすでにフッターがある。21 回目のスクロールは無い。ローディングのあいだは出さない。揃って足したあとに出す。初回で全部出ても残り 0 なのでフッター。`?tag=` も同じで、そのタグの展示が上限。カタログ全体ではない。トップの乱数は URL に残さないので、リロードで別の先頭になりうる。棚と lab は順が固定。

4コマの枠は比を先に取る（画像待ちでカードが伸びない）。タイトルの 1 行／2 行は、出したカードのレイアウトに任せる。覚えない。上に戻っても、残っている DOM なので飛ばない。

足したカードの中身は4コマ。`components/framesTemplate.svelte`（カードの `mount` と一緒。切り替え自体は CSS）。

トグルはカードごと。他のカードは触らない。More で extra を開く。4コマは残す。下に遊びと解説を足す。高さは伸び縮みする。

遊びを出すとき（開いた extra の中）:

1. 遊びの根っこを `unmount` する（既にあれば）
2. `/partial/{slug}/play/` を `fetch` する
3. extra の play へ入れる
4. 対応する JS を import して `mount`

HTML 内の script は実行しない。`mount` は `unmount` を返す。DOM を捨てるだけでは、ドラッグの処理が裏に残ることがある。入れ替え前に必ず `unmount` する。

`play.ts` の動きは詳細の遊びと同じもの。詳細も 404 も、同じ `/partial/{slug}/play/` を取って `mount` する。ソースを二つ持たない。

4コマ（`components/framesTemplate.svelte`）:

1. コマは全部 DOM に置く。`src` は最初から付ける（`loading="lazy"`）
2. 先頭はタイトル。そのあと `frame1.svg` から連番
3. 切り替えは CSS の keyframes。間隔は meta の `interval`。押し上げ 0.3 秒はそのあと
4. 次へは下からせりあげる。最後の次も同じ押し上げでタイトルに戻る。白待ちはしない
5. 取れなかったコマは `imageUrl("site", "missing.svg")` に差し替えて進む。そこで止めない
6. keyframes は slug ごとに `style#frames-anim` へ一度。カードの中に `<style>` は置かない（`mount` のたびに CSS が増えない）

箱を持ち上げるなどの本番は遊びと詳細だけ。4コマにキャプションは付けない。代替テキストや `prefers-reduced-motion` は後回し。

`/lab` も殻。埋め込みの lab 一覧からカードを組み立てる。トグルも乱数も無い。順は `published` の降順。足し方・残し方・上限・幅の収まりはトップと同じ。

## 7. 後回しにしてよい技術

- View Transitions
- 関連の自動提案。表示時には使わない
- 言語パス（`/en/...`）と言語切替
- タグ検索を、索引へ行く以外のその場絞り込みにするか
- 証書の見た目の詰め
- 索引の閉じた行に絵を乗せるか、名前で減らす入力か
- 4コマの a11y（代替テキスト、`prefers-reduced-motion`）
- 4コマの切り替え時間の詰め（押し上げ 0.3 秒は仮）。画面外では止めるか
- 一覧の追加 20 回の詰め。`--card-max` は 864px。画面外 DOM を外す仮想化は、この上限で足りなくなってから
- PC 向けの使いやすさ（複数列、サイドバー、ホバー前提の操作）
- 12 行グループでスクロール位置を戻すときの、先頭の合わせ方の詰め
- サイトマップ作製: `@astrojs/sitemap`。`site` と `base` は既にある。ビルドで `sitemap-index.xml` が出る。`/partial/` と `404.html` は載せない。Jekyll の `jekyll-sitemap` は使わない
- Search Console 登録: URL プレフィックス `https://cattyverse.com/schrodinger-likes-cats/`。所有権確認は HTML ファイル。ドメインを移したあとに一度だけ
- サイトマップ URL 送信: `https://cattyverse.com/schrodinger-likes-cats/sitemap-index.xml` を 1 回送る。デプロイのたびに ping はしない（廃止済み）
- 画像の CORS。`<img>` で出すだけなら要らない。遊びが SVG を canvas へ描いて読み出すようになったら、R2 側に足す
- R2 へ押す手順のスクリプト化。いまは rclone を手で叩く
