# レスポンシブ

画面の幅に対して、展示をどう置くかだけ書く。何を作るかは `docs/企画書.md`。ファイルの持ち方は `docs/概要説明.md`。列・形式・カードの中は三文書で同じ。

---

## 1. 方針

白い空間に展示を置く。カードでキャンバスを分割しない。外枠は持たない。

基準はスマホ。レイアウトも合図も、**一番狭い幅で組む**。狭くなったら積みに切り替える、ではない。最初からその幅の形であり、広くなっても並びは変えない。PC は同じ形を大きくしたとき違和感がない程度。サイドバー、複数列、ホバー前提の操作など、PC 向けに使いやすくすることは今はやらない。

一覧は **常に 1 列**。カタログを横に敷き詰めない。窓が縦なだけ、空間は白い。

カードの最大幅は固定値。FHD（1920 CSS px）の n% を計算して、そのピクセルを `--card-max` にする。n はあとで決める。いまの窓の `n%` や `vw` ではない。

窓が最大より狭い（スマホ、多くのタブレット）→ 全幅。  
窓が最大より広い（PC）→ 最大で止まり、中央。左右はキャンバス。

機種名では分岐しない。`@media` で列を切り替えない。横持ち専用レイアウトは持たない。

レイアウトの基準は **一番狭い幅**（360 CSS px。いまの Android の最頻）。カードの中はその幅で組んだ形のまま。広くなっても `@container` で組み替えない。一覧の箱が `--card-max` を超えるかだけ見て、全幅か中央かを決める。

密度（DPR）はレイアウトに使わない。イラストを SVG にするので、サイズ違いの書き出しも要らない。

## 2. 用語


### 幅と密度


| 用語 | 意味 | このサイトでの使い方 |
| --- | --- | --- |
| CSS px | レイアウト用のピクセル。パネルの画素でも、インチでもない | 最大幅も文字も、この単位で決める |
| DPR | Device Pixel Ratio。物理画素 ÷ CSS px。Retina はだいたい 2〜3 | レイアウトに使わない。SVG ならファイル選びにも使わない |
| ハードウェア解像度 | パネルの物理画素数（4K、8K など） | 見ない。4K でも OS 拡大で CSS 幅は Full HD 前後になりうる |
| インチ（対角） | 画面の実寸 | 見ない。Web は実寸をほぼ知らない |
| ズーム / OS 拡大 | CSS px の実寸を変える | 効く。拡大すると CSS 幅が減り、全幅に戻りやすい |
| FHD | 1920×1080。比は 16:9 | カード最大幅の参照。`1920 * n%` を固定値にする。OGP のサイズではない |
| 7680 CSS px | 8K を拡大率 100% で全面にしたときの幅 | 1 枚の画面としてはまず出ない上限。列は増えない。中央寄せの白が増える |


映画館のスクリーンでも、ページが使う幅は何メートルかではなく、その窓が何 CSS px か。1920×1080 を巨大スクリーンに映せば、1 列のまま、画素の実寸だけ伸びる。

単位に `vm` は無い。よくあるのは `vw` の言い間違い。


### 画像の形式


| 用語 | 意味 | このサイトでの使い方 |
| --- | --- | --- |
| SVG | 線と面で描く画像。拡大してもにじまない | 画面のイラスト（ロゴ、フック、猫、箱、4コマ）。一枚で全幅・全 DPR |
| viewBox | SVG の中の座標の箱 | 必須。無いと枠に合わせられない |
| WebP | 写真向きのラスタ | 写真、または写真に見える塗り・質感のときだけ。一枚（カード最大幅の 2 倍くらい）。サイズ違いは作らない |
| PNG | ラスタ。透過できる | OGP と関連用。1200×630。画面用の主形式にはしない |
| JPEG | ラスタ。写真圧縮 | OGP には使わない（PNG に固定） |
| GIF / アニメ WebP | 動くラスタ | 持たない。4コマはコマ送り |
| OGP | SNS のリンクプレビュー | SVG は使えない。PNG 1200×630。標準が変わったら変える |
| 1.91:1 | SNS の大きいプレビューの比（1200÷630） | OGP の比。FHD（16:9）だと上下が少し切れることがある |
| 1200×630 | Facebook 系の大きいプレビュー推奨。下限 600×315 の 2 倍 | OGP の目安。切れずに収まるサイズであって、他サイズ禁止ではない |
| srcset | 幅や DPR ごとにファイルを分ける HTML | イラストでは使わない。SVG 一枚 |


よくあるイラスト（線、ベタ塗り、手書きのぶれ）は SVG。円や多角形である必要はない。パスと塗りならベクトル。筆の粒、紙の質感、スキャン、写真は WebP。自動トレースで点が何万も付くなら WebP 一枚に戻す。


### CSS の単位と関数


| 用語 | 意味 | このサイトでの使い方 |
| --- | --- | --- |
| `%` | 親の幅（または高さ）に対する割合 | スロットいっぱいの絵、入力の幅。一覧は `width: 100%` |
| `em` | 親の `font-size` を 1 とした大きさ | 余白、タイトル、入力の padding。カードの文字に連れる |
| `rem` | ページ根っこの `font-size` を 1 とした大きさ | タップの床（`min-height: 2.75rem` など）。カードが狭くてもこれ未満にしない |
| `vw` / `vh` | 窓（ビューポート）の幅 / 高さの 1% | 使わない。最大幅は固定値。カードの中でも使わない |
| `cqi` | コンテナのインラインサイズ（だいたい幅）の 1% | カード幅に対する文字。`font-size: clamp(…, 4.2cqi, …)` |
| `cqw` / `cqh` / `cqb` | コンテナの幅 / 高さ / ブロックサイズの 1% | 横書きなら中の割合は `cqi` で足りる |
| `clamp(最小, 希望, 最大)` | 希望を、最小と最大のあいだに収める | 文字も入力も。狭すぎ・広すぎを止める |
| `minmax(a, b)` | トラックの最小と最大 | カード内フォームで使うことはある。一覧の列には使わない |
| `min()` / `max()` | 小さい方 / 大きい方 | カード内で使うことはある |
| `aspect-ratio` | 枠の横÷縦を先に決める | 4コマと SVG の箱。画像待ちでカードが伸びない |
| `width` / `height`（HTML） | 画像の内在サイズ。比のヒント | SVG にも付ける。表示サイズは CSS が決める |
| `max-width` | これ以上広げない | 一覧の `--card-max`。固定値 |
| `margin-inline: auto` | 左右の余白を均等に | 最大より広い窓で中央寄せ |


### レイアウト


| 用語 | 意味 | このサイトでの使い方 |
| --- | --- | --- |
| Grid | 二次元のマス。行と列 | 狭い幅で組んだフォームを置くとき。一覧は 1 列 |
| Flex | 一次元の並び | チェック＋ラベルなど、狭い幅でも横に置く操作 |
| `auto-fill` | 入るだけ列を作る | 一覧では使わない。常に 1 列 |
| `auto-fit` | 空の列を畳む | 使わない |
| `@media` | 窓や端末の条件 | 列・カード内の切り替えには使わない。DPR でも変えない |
| `@container` | 指定した箱の幅などの条件 | 並びの切り替えには使わない。狭い幅で組むので「狭くなったら」が無い |
| `container-type` | その箱を測れるようにする | カードに `inline-size`。`cqi` のため（文字の割合） |
| `pointer: coarse` | タッチ向きのポインタ | 入力の大きさをこれで変えない。タップの床は常に付ける |

## 3. 何を見て何を決めないか


| 見るもの | 決めること | 決めないこと |
| --- | --- | --- |
| 一覧の箱の CSS 幅 | 全幅か、最大で中央か | 列数（常に 1） |
| 一番狭い幅（360） | 中の並び・遊び・入力の形 | 広くなったときの別レイアウト |
| DPR | Canvas に描くときの裏の画素だけ | 列数、文字サイズ、SVG のファイル |


やらないこと:

- `@media (min-width: 768px)` で 2 列にする（iPad 判定）
- `@media (orientation: landscape)` で横持ち用レイアウトにする
- `@media (min-resolution: 2dppx)` で文字や列を変える
- `50vw` を最大幅にする（スマホが半分になる）
- 余りをカードに吸わせて敷き詰める
- PC 向けにサイドバーや複数列、ホバー前提の操作を足す
- カードが広いから、中のフォームを横並びに切り替える
- 狭くなったら積みに切り替える（最初から狭い幅で組む）
- 高解像度だから見出しを大きくする
- 8K 用の特別レイアウトを足す
- イラストの 400 / 800 / 1200 の三枚

## 4. 一覧（1 列）

列は増やさない。出す枚数は行数そのもの。列数を JS で読む必要はない。

```css
.stack {
  width: 100%;
  max-width: var(--card-max); /* 1920 * n%。固定値。n はあとで */
  margin-inline: auto;
}
```

窓 &lt; `--card-max` → 全幅。  
窓 &gt; `--card-max` → 最大幅、中央。左右はキャンバス。

組む幅は 360 CSS px。いま売れて使われている下限の本体（Android の最頻。小さい iPhone は 375）。これで形を決める。最大幅の式には使わない。広くなっても、この形のまま割合で少し動くだけ。

320 は初代 SE などレガシーの尻尾。ここで組まない。壊れなければよい。


### 典型的な結果（機種判定ではない）

n を大きめに取るので、こうなりやすい。n 次第でタブレット横は中央寄せになりうる。


| 窓の CSS 幅の目安 | 見え方 |
| --- | --- |
| スマホ縦（〜400） | 1 列。全幅 |
| スマホ横・タブレット縦 | 最大未満なら全幅。最大を超えれば中央 |
| ノート・PC | 1 列。中央。左右はキャンバス |
| それ以上 | 同じ 1 列。白が増えるだけ |


横持ち専用にはしない。幅が最大未満なら全幅のまま。YouTube の視聴ページのような横持ちレイアウトは持たない。

巨大な窓でも列は 1。7680 CSS px でもカードは `--card-max`。余りはキャンバス。

リサイズや縦横の切り替えで列は変わらない。カード幅は変わりうる（全幅 ↔ 最大）。カードは `unmount` しない。スクロール位置の戻し方は概要説明（12 行グループ）。高さは幅で変わるので、目安である。

## 5. カードの中

外は 1 列。中は、一番狭い幅で組んだ形。広くなっても並びを変えない。「狭くなったら積む」ではない。

同じ遊びが詳細の広いスロットに入っても、同じ CSS が効く。詳細の箱も同じ `--card-max` で止めれば、カードと詳細の遊びは同じ幅になる。

```css
.card {
  container-type: inline-size;
  font-size: clamp(0.875rem, 4.2cqi, 1.125rem);
}

.card h2 {
  font-size: 1.25em;
}

.card .desc {
  margin-block: 0.75em;
}
```

ルートを `cqi` にしておくと、タイトルも余白も `em` で同じ割合になる。遊びのドラッグ範囲は、スロットの `%`。座標は CSS px。Canvas に描くときだけ、裏の画素を `devicePixelRatio` 倍にする。当たり判定は CSS px のまま。

`@container` で中を切り替えるのはやらない。

## 6. 画像

SVG は解像度には効く。枠の高さは形式では決まらない。枠に `aspect-ratio` を先に置く。

```css
.slot {
  aspect-ratio: 4 / 3; /* 展示の比。仮 */
}

.slot img {
  width: 100%;
  height: 100%;
  display: block;
}
```

```html
<img src="frame1.svg" width="400" height="300" alt="">
```

`srcset` も `@2x` も作らない。OGP は画面用 SVG とは別に、同じ絵を PNG 1200×630 で一枚。`meta.image` はそのファイル名。中心に描く。FHD で出しても壊れないが、比は 1.91:1 に合わせる。

## 7. 文字

DPR やパネル解像度では変えない。高 DPI では OS とブラウザがすでに CSS px を厚くしている。`2dppx` だから `font-size` を上げると、スマホの文字だけ巨大になる。4K を 100% のまま使って小さく見えるのは、サイトではなく拡大率の問題。

巨大ディスプレイでもカードは `--card-max` で止まる。窓が 7680 CSS px でも、展示の文字はカード幅のまま。壁いっぱいに見出しを伸ばさない。

カード幅が 360〜最大のあいだで動くなら、その範囲だけ `clamp`。最大付近で読みやすければ、固定の `rem` でもよい。

## 8. フォームと入力

遊びの中には SVG だけでなく、テキストボックス、チェックボックス、解答ボタンも入る。並びは一番狭い幅で決める。広くなっても組み替えない。

狭い幅でも成立する形の例（積みに「切り替える」のではなく、最初からこう組む）:

```
| SVG            |
| テキスト        |
| テキストボックス |
|          [解答] |
```

チェックとラベルは、狭い幅でも一つの操作として横に置いてよい（Flex）。

```html
<form class="play-form">
  <div class="art"><img src="q.svg" width="400" height="300" alt=""></div>
  <label for="ans">テキスト</label>
  <input id="ans" type="text">
  <button type="submit">解答</button>
</form>
```

```css
.play-form {
  display: grid;
  gap: 0.75em;
}

.play-form .art img {
  width: 100%;
  aspect-ratio: 4 / 3;
}

.play-form input[type="text"] {
  width: 100%;
  min-width: 0;
  font: inherit;
  min-height: 2.75rem;
  box-sizing: border-box;
  padding: 0.4em 0.6em;
}

.play-form button {
  justify-self: end;
  font: inherit;
  min-height: 2.75rem;
  padding: 0.4em 0.9em;
}
```


| 要素 | 置き方 |
| --- | --- |
| テキストボックス | `width: 100%`。高さは `em`、床は `min-height` |
| チェック / ラジオ | 箱＋ラベルは Flex の 1 行。当たる箱は 2.75rem 以上 |
| 解答ボタン | 末尾。`justify-self: end`。伸ばしすぎない |
| SVG | 上。全幅 |


`font: inherit` が要点。ブラウザ既定の小さい入力を残すと、カードの文字とずれる。見た目は `em` / `cqi` / `%`。押しやすさの床は `rem`。入力の大きさを DPR や `vw` で変えない。

箱をドラッグする遊びはフォームではない。スロット内の `%`（箱の幅・可動域）。`min-height` とは別。

## 9. 詳細・404・巨大画面

詳細の遊びはカードを開いたときと同じ部品。レスポンシブも同じ。詳細の本文箱も `--card-max` で止め、中央寄せすれば、一覧と詳細で遊びの幅が揃う。画面幅の別 CSS は持たない。

404 の遊びも同じ。窓枠は付くが、遊びの基準はスロット幅。

巨大な窓、横持ち、DevTools、分割画面は、いずれも箱の CSS 幅が `--card-max` を超えるかどうかだけ。特別な向き用レイアウトは持たない。PC で左右が空くのは、空間が見えている状態であって、PC 用の別画面ではない。

## 10. 仮の数

実装で詰める。ここは出発点。


| 名前 | 仮 | 役割 |
| --- | --- | --- |
| `--card-max` | FHD の n%（固定 px。n は未定） | カードと一覧の最大幅。これ未満は全幅、以上は中央 |
| 組む幅 | 360 CSS px | レイアウトを決める幅。Android の最頻 |
| 320 | レガシー | ここで組まない。壊れなければよい |
| カードの `font-size` | `clamp(0.875rem, 4.2cqi, 1.125rem)` | 中の文字の根っこ |
| タップの床 | `2.75rem` | だいたい 44 CSS px |
| 4コマの比 | 4 / 3 | 展示ごとに決めてよい。枠は先に取る |
| OGP | PNG 1200×630 | 標準が変わったら変える |
